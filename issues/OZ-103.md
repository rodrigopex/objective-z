## Context

Noticed while adopting the PAL's `struct oz_metadata` as the root object's
`_meta` field (PR #224). That struct already has the bit this needs, and its
own comment names the exact use case:

```c
/*   [12]   immortal       — skip dealloc (singletons, literals) */
uint32_t immortal        :  1;
```

oz_static never sets or reads it. `grep -rn immortal tools/oz_static/src`
finds only prose in comments.

## Input

A boxed string literal, which `emit::render_boxed_string_literal` turns into
a `static` instance:

```objc
OZString *greeting = @"hello";
```

## Observed

The generated definition marks the object as *already being deallocated*, so
that the release path's re-entrancy guard makes release a no-op:

```c
struct OZString _oz_str_L12_C21_1 = {
        .base = { ._meta = { .class_id = OZ_STATIC_CLASS_OZString,
                             .deallocating = 1 },
                  .oz_refcount = 1 },
        ._length = 5, ._hash = 0, ._data = "hello" };
```

and `oz_static_release` (companion.rs) reads it back:

```c
if (self->_meta.deallocating) {
        return;
}
self->_meta.deallocating = 1;
```

It works, and the literal is correctly never freed — the reason it matters
is that the field says something false. `deallocating` means "teardown is
running right now"; here it means "never tear down". Anyone reading the
generated C, or adding a second reader of that flag, has to know the trick.

## Expected

Set `._meta.immortal = 1` on a literal, and have the release path check
`immortal` before the refcount decrement. `deallocating` then keeps its one
real meaning, which the re-entrancy guard still needs.

Worth doing at the same time: singletons. `oz_platform_types.h` names them
alongside literals as the intended users of the bit, and
`Singleton+Protocol.h`'s `+sharedInstance` objects are equally immortal —
currently nothing marks them, so they rely on never being released.

## Workaround

None needed; the current behaviour is correct. This is about the generated C
saying what it means.

## Discussion

- **MAINTAINER (2026-08-30):** Small but touches the release path, which is
