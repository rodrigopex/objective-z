## Context

Compiling every sample's generated output with `-Wall -Wextra` and counting
warnings by kind (PR #224 did this to find three real defects, one of which
was a wrong return type). Three kinds were found and fixed; this is what is
left:

```
58 [-Wunused-parameter]
```

Nothing else. `-Wall` is clean.

## Input

A method whose body does not use every parameter — most often an empty
`-dealloc`:

```objc
@implementation OZObject
- (void)dealloc
{
}
@end
```

## Observed

```
Foundation/OZObject.c:28:40: warning: unused parameter 'self' [-Wunused-parameter]
   28 | void OZObject_dealloc(struct OZObject *self)
```

The bulk are `self` in an empty `-dealloc`. The rest are genuinely unused
method parameters whose source bodies ignore them, e.g.

```
OZObject.c:39: unused parameter 'self'
OZObject.c:39: unused parameter 'buf'
OZObject.c:39: unused parameter 'maxLen'
   39 | int OZObject_cDescription_maxLength_(struct OZObject *self, char* buf, int maxLen)
```

Not a defect in the transpiled program, and **not currently a build
failure**: `-Wunused-parameter` comes from `-Wextra`, which Zephyr's default
warning set does not include. All 13 samples build for `mps2/an385` and pass
twister as they are.

## Expected

Emit `(void)param;` at the top of a translated method body for each
parameter the body does not reference — the same acknowledgement the SDK's
own C already uses (`(void)inner;` in `oz_platform.h`'s heap stubs,
`(void)expr;` in `oz_sdk/assert.h`).

Two things to get right:

- Decide by whether the *body* references the name, not by heuristics on the
  signature. A parameter used only inside a nested block literal still
  counts as used.
- `self` is the common case and worth handling for its own sake: an empty
  `-dealloc` is idiomatic Objective-C, so the warning fires on correct code.

## Workaround

None needed. A target that wants `-Wextra -Werror` over generated C cannot
have it yet.
