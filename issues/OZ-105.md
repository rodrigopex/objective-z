## Context

PR #224 makes `OBJZ_BACKEND_STATIC` the default and verifies it on
`mps2/an385` (ARM): all 13 samples build, all 13 pass twister. RISC-V was
not tried, and it is a documented target — `justfile` defines
`riscv_board := "qemu_riscv32"` and `CLAUDE.md` documents
`just board=qemu_riscv32 rebuild`.

This is worth doing precisely because ARM already passes. A second
toolchain is the cheapest way to find anything ARM-specific that slipped
into the generated C, and the ARM run of this same work showed how much a
new toolchain surfaces: it found five defects in twenty minutes after a full
day of green host checks (see `tools/oz_static/PARITY.md`, "On target").

## Input

```sh
west twister -T samples/ -p qemu_riscv32 -O /tmp/twister-riscv
# or one sample:
just board=qemu_riscv32 project_dir=samples/arc_demo rebuild && just run
```

## Observed

Not run. No claim either way.

## Expected

Samples build and pass on `qemu_riscv32` as they do on `mps2/an385`, or the
differences are understood and recorded.

Things worth watching, given what ARM turned up:

- **Alignment.** `pools::SLAB_ALIGNMENT` is 4 and `OZ_SLAB_DEFINE` takes it
  as a literal. RV32 agrees, but the value is not derived from the target.
- **`struct k_spinlock` again.** It is empty only when `CONFIG_SMP` and
  `CONFIG_SPIN_VALIDATE` are both off; a RISC-V board with different
  defaults exercises the other shape of `oz_spin_init` (OZ-104's sibling fix
  in PR #224).
- **The Clang target triple.** `cmake/ObjcClang.cmake` maps a target to a
  triple for the AST dump, and CLAUDE.md notes RISC-V needs real LLVM rather
  than Apple Clang. Worth confirming `objz_find_clang()` picks the SDK's
  LLVM, since `OZ_CLANG` is only honoured by the test harnesses.

## Workaround

None needed. ARM is the verified platform; RISC-V is simply unmeasured.
